# Dataset discovery: approach (draft)

**Status:** draft, 2026-10-01. This is Claude's version of the ChatGPT "AI-assisted dataset discovery roadmap" (2026-09-23), adjusted for Robert's decisions and what the code shows.

**Labels:** **C** = confirmed in code or repo; **H** = hypothesis or proposal; **D** = decided by Robert.

## Goal

Build a **curated, evidence-backed inventory of public geospatial datasets relevant to health research** (D): environmental exposures and social determinants of health that OHDSI researchers would plausibly link to patient locations.

It answers two questions per dataset:

- What exists?
- Could Gaia take it in?

An entry saying "exists, checked, no recipe yet" is a useful result in its own right.

**Not the goal yet:** harvesting a large catalog, generating recipes, or AI-written ETL.

## Principles (kept from the roadmap)

1. **Discovery does not depend on harmonization.** An entry is useful long before anyone writes a recipe.
2. **Every fact needs a source.** Record the URL or document passage behind each field. Unknowns stay blank: never guess units, dates or geography.
3. **Independent status axes, not one linear state:**
   - **existence**: is the publisher page reachable? Last checked when?
   - **characterization**: how many fields are filled, with evidence?
   - **recipe**: none, proposed, or exists in gaiaCatalog;
   - **recipe health**: last load result, if any.
4. **A dataset is not the same as its release.** One row per underlying dataset. Releases (years, geographic subsets, resolutions) go in a column or a linked row, not as duplicate datasets.
5. **AI helps with reading and summarizing documentation, not with inventing facts.** Every LLM-extracted field still needs its source.

## What changed from the ChatGPT version, and why

| Roadmap said | Changed to | Why |
|---|---|---|
| Start with a big catalog (Data.gov), a few hundred records | **Start curated:** a hand-picked list of health-relevant publishers and datasets | D. Health relevance matters more than breadth for Gaia's users. Data.gov's geospatial records are numerous and duplicate-heavy (H). |
| Define a new minimal skeleton schema | **A separate staging list** (`inventory.csv`), promoted later to template records | D. Keeps entry cheap. Its columns line up with DCAT/SOSO fields, so promotion to `ohdsi-gis-metadata-template` / gaiaCatalog JSON-LD is mechanical (H). |
| Recipe health is a later workstream | **Track recipe health from day one** for datasets already in gaiaCatalog | The deployment tests found real failures: SEDAC timing out, the SVI 2018 404, flaky Census FTP, a credential committed in a script, and `datestamp` written after a failed download. |
| Open question: are per-dataset scripts generated or hand-maintained? | **Partly answered** | They are generated by an external `etl()` generator (GDSC/Miami) (C, per earlier review). Whether that generator should be the contribution model is still open. `../manuscript/design-drift-explained.md` covers the older metadata-driven path. This does not block discovery. |

## Staging list: `inventory.csv`

One row per dataset. Lists inside a cell are separated by `;`.

| Column | Meaning | Maps to (H) |
|---|---|---|
| `id` | Short slug, Gaia style (for example `us_cdc_svi`) | — |
| `title` | Publisher's title | `dct:title` / `schema:name` |
| `publisher` | Organization | `dct:publisher` |
| `domain` | `environment`, `sdoh`, `health_outcome`, `built_env`, `boundaries`, `climate` | `dcat:theme` |
| `landing_url` | Canonical publisher page | `dcat:landingPage` |
| `access` | `download`, `api`, `api_key`, `registration`, `request` | — |
| `geography` | Units, for example `tract;county` or `grid_1km` | `dct:spatial` |
| `coverage` | For example `US`, `global`, `MA` | `dct:spatial` |
| `temporal` | Years available, for example `2000-2022 biennial` | `dct:temporal` |
| `format` | For example `csv;shp;gdb;geotiff;netcdf` | `dcat:mediaType` |
| `license` | As stated by the publisher | `dct:license` |
| `update_cadence` | As stated | `dct:accrualPeriodicity` |
| `in_gaia` | gaiaCatalog `table_id`(s), if any | — |
| `recipe_health` | `ok`, `broken`, `untested`, with the date | — |
| `last_checked` | Date the landing page was last checked | — |
| `evidence` | URL(s) supporting the row | — |
| `notes` | Open questions and caveats | — |

## Candidate publishers to evaluate (unverified)

Starting points, not claims. Availability and URLs change, and some U.S. federal environmental-justice tools were reportedly withdrawn or moved in 2025. Verify each one before adding a row.

- **Air quality:** EPA AirData / AQS (annual and daily summaries); CDC Environmental Public Health Tracking (PM2.5 and ozone estimates); NASA SEDAC / Earthdata gridded PM2.5.
- **Social vulnerability and deprivation:**
  - CDC/ATSDR Social Vulnerability Index and Environmental Justice Index;
  - Area Deprivation Index (Neighborhood Atlas);
  - NaNDA (National Neighborhood Data Archive).
- **Demographics and boundaries:** Census ACS (API) and TIGER/Line boundaries.
- **Health outcomes, area level:** CDC PLACES.
- **Built environment and food:** USDA Food Access Research Atlas; EPA Smart Location Database.
- **Climate and hazards:** NOAA climate normals and heat; PRISM; FEMA National Risk Index.
- **Global** (for the Tanzania and Kenya work already in the catalog): WorldPop, Copernicus, OpenStreetMap-derived layers.

## First experiment (proposal)

1. Seed rows for the 22 catalog datasets, with recipe health filled in from the tests.
2. Add about 30–50 curated candidates from the publishers above, filling only the evidenced fields.
3. Measure:
   - how many rows have a verified landing page;
   - how many fields are filled with evidence;
   - how many rows are "verified, no recipe";
   - how long a row takes, by hand and with AI help.
4. Review with Robert, then decide whether to automate any part, such as periodic link checks or LLM-assisted characterization.
